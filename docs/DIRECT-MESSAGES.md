# 私信（2026-11-03）

## 使用方式

- “我的 → 私信”查看会话与未读；同学的公开主页提供“发私信”。只给已验证、绑定后的账号使用，不为访客自动创建新身份。
- 每一对账号只有一个会话。陌生人先发一条申请；接收者接受后双方才能继续发消息，拒绝后该发送者不能重复申请。
- “私信 → 设置 → 拒绝陌生人私信”：默认关闭（允许单条申请）。开启后拒绝新的申请，已接受的会话可以继续。这里的陌生人指尚无已接受会话的人，不依赖关注关系。
- 支持纯文字，每条 1–1000 字；不接图片、语音、群聊、站外推送。聊天页可见时约每 5 秒更新，其他私信页约 15 秒，其他页面未读检查约 60 秒；后台不轮询。手动刷新可用。
- 收件箱每页 50 个会话，聊天每页 30 条。输入草稿仅存内存，失败保留，离开再回来仍可继续；切换身份或退出清空。重复发送沿用请求 UUID，避免网络重试重复插入。
- 拉黑双方均不能再发消息，已有历史保留，可从设置解除。点击对方消息的“⋯”举报，只提交所选消息。

## 数据与权限

独立迁移：`supabase/migrations/20261103060728_private_messages.sql`。只新增，不改旧帖子、照片、足迹或公开范围。六张表均在未暴露的 `xuetuan_guard`，启用 RLS，anon/authenticated 无直接表权限：

| 表 | 内容 |
| --- | --- |
| dm_preferences | 本人是否接收申请 |
| dm_threads | 成员对、申请状态与各自已读游标 |
| dm_messages | 文字、发送者、唯一请求 ID、序号 |
| dm_blocks | 本人拉黑关系 |
| dm_reports | 被举报的单条消息快照与原因 |
| dm_audit | 管理处理审计 |

公开 API 为三个 security-invoker RPC：`xuetuan_dm_read`、`xuetuan_dm_write`、`xuetuan_dm_moderation`，仅 authenticated 执行；私有 helper 固定空 search_path，重新检查 Auth 的已验证/非匿名身份、参与者、接收偏好和双方拉黑关系，不相信客户端成员 ID。

写入复用现有账号/浏览器封禁与服务端限流。普通私信操作 60 次/分钟、500 次/天；新会话申请另限 3 次/分钟、10 次/天；举报复用 3 次/分钟、20 次/天。已读确认不消耗写入额度，但仍仅允许本人会话、单调推进且不超过最后消息序号。

管理员界面仅返回待处理举报的单条正文快照、昵称、原因、时间与举报 ID；不返回会话 ID/完整历史。管理员也不能用普通读取接口查看非本人会话。可以忽略、移除单条、移除并封禁作者及已知浏览器；后台留审计。消息仍保存在数据库，非端到端加密，运维数据库权限不等同于应用内权限。
