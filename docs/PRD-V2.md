## 一、项目定位与设计目标

雪团（XueTuan）最初是一个旅行足迹地图项目，后来逐步扩展为面向厦门大学马来西亚分校（XMUM）学生的美食、旅行与校园分享平台。

产品核心不是简单复制美团、小红书、Instagram 或 Google Maps，而是建立一个：

**以地点为中心，以个人足迹为基础，以校友分享和探索为社交连接方式的校园生活平台。**

主要希望解决三个问题：

1. 用户能够记录自己的旅行、美食经历，形成长期积累的个人地图。
2. 用户能够发现其他校友推荐的餐厅和旅行目的地，收藏自己想去的地方。
3. 用户能够通过地点、照片和动态了解其他校友的经历，产生浏览兴趣及自然的社交互动。

产品最初面向 XMUM，以中文为起点，未来支持英文和其他国际学生。

需要特别重视：

**用户为什么第一次打开雪团，以及为什么愿意持续使用。**

不能仅仅为了增加功能而开发功能。

## 二、底部主导航：确定为四个栏目

建议采用：

**首页｜探索｜足迹｜我的**

不再单独设置一个名为「社区」的底部主栏目，而是将校园图文动态整合到首页。

### 1. 首页（Home）

定位：首次进入雪团的默认页面，负责内容发现与吸引用户持续浏览。

采用「地图预览 + 校友图文信息流」的混合形式。

主要包括：

- 顶部品牌、搜索入口、消息通知。
- 一块可以点击的地图预览。
- 最新、推荐、附近、关注等内容筛选（可分阶段开发）。
- 校友最近分享的美食、旅行记录。
- 带照片的图文卡片。
- 帖子关联地点、作者、评分、发布时间。
- 收藏、点赞、评论等操作。

交互要求：

- 点击地图预览，跳转到底部「探索」栏目，打开完整地图。
- 点击图文卡片，直接进入帖子详情，而不是先跳转到地图。
- 点击帖子中的地点，可以在探索地图上定位。
- 点击作者头像，可以查看其公开主页及公开足迹。
- 点击收藏，可将地点加入心愿清单。

首页是纵向可滚动页面，不需要一直固定显示半屏地图。

地图预览负责展示地图特色，图文负责展示新鲜内容。

现阶段真实内容较少，应设计合理的空状态，不要用大量虚假内容制造活跃假象。

后期根据用户行为数据，再决定是否增加图文信息流占比。

### 2. 探索（Explore）

定位：完整公共地图，负责空间探索与地点发现。

保留现有地图技术实现和交互能力，避免不必要的重构。

地图有两个核心分类：

**吃（Food）｜玩（Travel）**

吃：

- XMUM 食堂、Bell 等步行可达地点。
- Kota Warisan、Salak Tinggi 等短途出行区域。
- IOI City Mall、Putrajaya、Cyberjaya 等中距离区域。
- 吉隆坡市区及更远的美食。
- 根据距离、评分、预算、区域等条件筛选。

玩：

- 国内外旅游城市、景点、旅行目的地。
- 全球地图探索。
- 查看其他校友的旅行照片、体验、评分与分享。
- 从地点跳转到相关用户或帖子。

地图功能：

- 展示公共地点标记。
- 地点评分为0–5分。
- 单个地点标记颜色按评分从灰色、橙色渐变至红色。
- 地点密集时进行聚合。
- 同一现实地点对应一个公共地点实体，可包含多名用户的不同体验。
- 点击地点标记后展示地点卡片、照片和评价。
- 支持列表与地图联动。
- 支持距离和评分筛选。
- 支持按记录更新日期筛选，如最近3天、7天、30天。
- 默认仍可查看全部地点，避免没有近期评价的地点直接消失。

特别注意：探索地图不再放「我的地图」「收藏」主选项。

这两个功能统一放到「足迹」栏目中。

### 3. 足迹（My Footprints）

定位：用户自己的美食与旅行地图。

主要设计两个切换：

**去过（Visited）｜想去（Wishlist）**

#### 去过

记录用户已经体验过的地点。

包括：

- 自己去过的餐厅、景点、城市和国家。
- 个人评分。
- 旅行照片。
- 体验评论。
- 到访年份或日期（可选）。
- 个人旅行图鉴。
- 个人地图。

未来希望支持精美的3D地球，将不同国家和城市的旅行足迹可视化。

全球视角可使用3D地球，城市及具体餐厅视角采用传统平面地图。

用户可以自由添加以前去过的地点，不需要在现场实时打卡。

#### 想去

记录用户收藏的、未来想体验的地方。

包括：

- 想去的餐厅。
- 想去的景点、城市和国家。
- 地图视图与列表视图。
- 自定义收藏夹（后续功能）。
- 从其他校友的分享一键收藏。

去过与想去是两个独立概念。

收藏一个地点不代表已经去过。

已经去过的地点也可以保留在收藏夹中，例如想再次光顾的餐厅。

用户不必被系统强制移除收藏。

#### 家乡标记

个人足迹地图中可以额外显示一个独立的「家」图标。

用于展示用户来自哪里。

家乡属于身份信息，不属于旅行记录，不需要评分，也不计入旅行足迹数量。

家乡标记的显示由用户隐私设置控制。

### 4. 我的（Profile）

定位：个人社交主页及账号管理，不应该只是设置页面。

建议包括：

- 头像、昵称、个人简介。
- 来自哪里（From）。
- 公开足迹数量。
- 我的帖子。
- 关注与粉丝（未来）。
- 收藏的帖子、游记等内容。
- 消息通知。
- 隐私设置。
- 语言设置。
- 账号管理。

需要区分：

地点收藏：放在「足迹 → 想去」。

帖子收藏：可以放在「我的 → 内容收藏」。

用户自己的公开主页应能展示公开的足迹、照片和帖子。

其他用户可以通过帖子作者头像进入该主页。

#### 未来私信功能

目前不需要占据底部主导航栏。

可以先在首页顶部或「我的」中设置消息入口。

未来如果开放私信，可统一到消息中心。

需要考虑用户是否愿意接收陌生人私信、拉黑、举报等基本安全机制。

## 三、家乡地图（From）功能

家乡地图是雪团的辅助特色功能，主要目的是展示 XMUM 学生来自世界哪些地区。

重要决定：**不要将家乡地图与吃、玩并列为第三个核心分类。**

探索地图仍以「吃 / 玩」为主。

### 入口设计

建议在探索地图右侧的图层按钮中增加：

**校友家乡（Hometown Layer）**

用户点击图层按钮后，选择是否显示家乡地图。

可以通过地图图层或独立的次级查看模式实现，尽量不干扰美食和旅游标记的日常使用。

个人家乡设置位于：

我的 → 编辑资料 → 来自哪里

填写信息：

- 国家
- 城市
- 区县（可选）
- 是否公开

不强制填写。

### 公共家乡地图

用户开启家乡图层后，可以查看自愿公开来源地的 XMUM 学生分布。

建议优先以国家、城市聚合显示人数。

不应默认暴露某个学生的详细家庭位置。

用户可以自愿公开自己的家乡和公开个人主页。

未来可以关联：

- 同乡校友。
- 某位校友的家乡旅行推荐。
- 该城市的美食和景点。
- 从家乡到 XMUM 的留学路线可视化。

但这些属于后续功能，不需要第一版全部实现。

### 家乡与个人地图的关系

雪团包含三个独立概念：

- From：来自哪里。
- Visited：去过哪里。
- Wishlist：想去哪里。

家乡不能和旅行足迹混淆。

## 四、统一的地点记录系统

雪团应该围绕地点构建统一的数据结构。

不要把「添加餐厅」「旅行打卡」「公共地点评价」「社区发帖」做成几套互不相关的系统。

用户的一次记录应当可以同时形成：

1. 个人足迹。
2. 对该地点的一条个人评价。
3. 公共地图的内容（若选择公开）。
4. 首页动态（若适合展示且用户选择公开）。
5. 其他用户可以浏览与收藏的内容。

例如用户在 Bell 吃了一家餐厅：

选择地点 → 添加照片 → 评分 → 写评论（可选）→ 选择公开权限 → 保存。

这样不需要重复发布。

对于一次旅行涉及多个地点的情况，可以将多条记录组成一篇旅行分享，而不是向首页连续推送几十条零散内容。

### 地点与用户记录应分离

同一餐厅可以有很多用户记录，但公共地图应尽量只有一个对应的地点标记。

不同用户的评分、照片、评论分别保存。

地点可有综合评分，用户也能看到每个人的独立评价。

需要考虑新增地点时的重复检测与合并机制。

## 五、旅行照片自动导入

这是个人足迹地图的重要潜在竞争力。

目标是减少用户手动填写大量旅行地点的时间。

建议支持：

**手动添加 + 相册批量导入**

### 批量导入流程

1. 用户自主选择照片。
2. 尽量在浏览器本地读取照片的 EXIF 日期及 GPS 数据。
3. 有 GPS 信息时，建议对应地点或城市。
4. 将照片按地点、时间分组。
5. 无GPS数据的照片允许用户手动选择地点。
6. 未来可考虑AI辅助识别地标，但用户需要确认识别结果。
7. 用户确认后批量加入个人足迹。
8. 选择照片与地点的公开权限。

### 隐私要求

- 不应未经允许扫描整个手机相册。
- 不应自动公开照片原始定位信息。
- 不应将AI猜测的地点当作确定事实。
- 用户应能删除、修改和隐藏记录。
- 默认避免公开个人的实时位置。

第一阶段优先实现可靠的手动添加，之后可以逐步增加批量导入。

## 六、首页与社区的关系

雪团不需要简单复制一个小红书社区。

它的内容应该主要围绕地点展开。

适合的内容包括：

- 最近吃了什么。
- 新发现的餐厅。
- 学校食堂的新菜。
- 周末去了哪里。
- 假期旅行记录。
- 家乡特色美食和景点。
- 旅行照片及相关地点。

首页负责通过照片、标题、时间和个人经历吸引用户。

探索地图负责帮助用户查看地点的地理位置、评价和相关记录。

两者需要互相联动。

**地图负责空间，信息流负责时间和新鲜感，个人足迹负责长期积累。**

## 七、产品粘性与用户持续使用

这是雪团最需要解决的产品问题。

不能因为地图看起来很漂亮，就认定用户会持续打开。

预期用户使用动机包括：

### 1. 第一次使用

- 创建自己的旅行足迹地图。
- 查看 XMUM 附近有什么好吃的。
- 看看其他校友去过哪些地方。
- 对地图形式的分享产生好奇。

### 2. 持续使用

- 不知道今天吃什么时搜索附近美食。
- 看到新餐厅或旅行地点后加入收藏。
- 吃饭或旅行结束后记录体验。
- 看校友最近发布的新内容。
- 浏览其他学生的旅行经历和照片。
- 通过共同的兴趣和地点与他人互动。

### 3. 长期积累

- 个人地图越来越完整。
- 已吃过的餐厅与去过的景点逐渐增加。
- 心愿清单越来越丰富。
- 形成可以回顾和分享的个人旅行图鉴。

### 4. 外部传播

未来支持将旅行地图、年度足迹、地点卡片生成图片或分享链接。

可以分享至 Instagram、微信朋友圈等现有社交平台。

雪团不需要强迫用户放弃其他社交平台。

## 八、UI/UX设计原则

1. 手机端优先。
2. 保留地图作为主要视觉特色。
3. 首页地图预览与图文结合。
4. 全屏地图放在「探索」栏目。
5. 避免堆积过多悬浮按钮。
6. 地图筛选应尽量简洁。
7. 用户可以直观地区分去过、想去、公共探索。
8. 点击地图标记能快速看到照片和评价。
9. 每条图文与实际地点关联。
10. 用户添加记录的流程尽量少步骤。
11. 保留现在已有的功能，避免无必要的整体重构。
12. 首页与地图都应支持真实数据不足时的合理空状态。

- 四栏导航：首页、探索、足迹、我的。

- 探索地图的吃/玩分类。
- 地点详情。
- 个人地点记录。
- 评分与照片。
- 去过/想去。
- 收藏地点。
- 公共与私人记录区分。
- 地点记录与地图数据关联。

### P1：社交内容与体验

- 首页真实信息流。
- 地点关联帖子。
- 公开用户主页。
- 点赞和评论。
- 地图与图文相互跳转。
- 时间筛选。
- 改善地图与地点列表联动。
- 家乡资料设置及个人家乡标记。

### P2：增强功能

- 3D旅行地球。
- 旅行照片批量导入及EXIF解析。
- 校友家乡公共地图。
- 地点收藏夹分类。
- 旅行路线与多地点分享。
- 校友推荐排行榜。
- 我的旅行图鉴。
- 可分享的旅行地图卡片。

### P3：未来根据需求决定

- 私信。
- 关注系统的深入功能。
- 拼饭、组局。
- AI旅行地点识别。
- 智能美食推荐。

## 十、对 Codex 的具体工作要求

当前雪团已有一定规模的前端页面和地图功能，不是从零开始的新项目。

请先完整检查当前代码和已有功能，再进行下一步开发。

第一步，请：

1. 分析当前项目的页面、路由、组件、数据结构和持久化方式。
2. 对照以上需求，指出已经实现、部分实现、尚未实现的功能。
3. 检查目前是否存在重复的地点、收藏、用户记录或帖子数据结构。
4. 提出最小改动的导航与数据结构调整方案。
5. 明确指出可能造成现有功能失效或数据丢失的修改。
6. 给出分阶段实施顺序。

在完成分析之前，不要直接重写整个项目。

请保持已有功能尽量可用，优先复用原有代码。

如果需求存在不确定性，先说明建议和取舍，不要擅自引入过多新功能。

产品最重要的目标不是功能数量，而是：

**让用户有理由第一次打开雪团、愿意留下自己的经历、能够发现其他学生的内容，并且有理由再次回来。**
