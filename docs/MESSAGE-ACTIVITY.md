# 统一消息入口（2026-11-03）

用户确认“消息”同时汇总点赞、评论与私信。我的入口下设三个分栏，不增加底部导航。

- 点赞按分享汇总，保留原有隐私：只有分享作者能读数量，不列点赞者昵称或身份；取消赞撤销提醒，再点赞作为新互动。
- 评论通知分享作者，回复同时通知主评论作者，去重并排除发送者本人。游客可以收到回复，私信继续要求绑定账号。
- 点击提醒确认当前内容仍可见、标记该项已读并打开原分享；提供分栏“全部已读”，只确认当次读取水位之前的消息，后来的互动不会误清。
- 提醒与已读状态在服务器按账号保存，主号、小号分别记录。公开分享转为私密、评论被删除时，相应提醒与未读立即隐藏；删除分享则级联删除提醒。
- 历史互动回填为已读。原点赞没有时间字段，显示“以前收到的赞”，不伪造日期。正文从现有评论读取，不复制到提醒表。
- 活动页面可见时约15秒更新，其他页面未读约60秒，后台停止检查；不是系统/微信推送。原私信会话5秒规则保留。

## 数据边界

已应用线上迁移：`20261103124558_message_activity.sql`。新增一张私有表 `xuetuan_guard.message_activity`，RLS 开启、无 anon/authenticated 直接表权限。写入只由点赞/评论触发器完成，不增加面向客户端的创建提醒接口。

两个公开 RPC 为 security-invoker、authenticated-only，内部固定 search_path，实际收件人只取 auth.uid()，不接收可伪造的收件人参数；管理员也不能用这些接口查看别人的提醒。游客的 authenticated 会话能查看本人的互动提醒，不开放任何私信权限。
