# lijianan331 主号／小号切换

用户要求：同一账号里能切换第二个身份。入口位于“我的”，仅已验证的 `lijianan331@gmail.com` 主号和它管理的小号可见。

## 行为

- 首次点击“切到小号”时，后端为该主号创建或恢复唯一的小号，默认昵称 `lijianan331的小号`；可以在小号里改昵称/头像。
- 小号为独立 Supabase Auth 用户，沿用现有 RLS。足迹、收藏、家乡、留言、点赞及公开主页独立；不复制、合并或改变主号既有记录。
- 主号管理员白名单不变，小号不写入管理员名单。切换会走现有 Auth 刷新流程，清除上一身份的照片缓存与互动草稿。记录草稿按现有用户 ID 分开保存。
- 两个身份的已验证登录会话保存在同一浏览器，用于快速切换；不进入数据导出、分享卡、日志或公开资料。退出登录清除两份本机登录信息，并尝试注销另一身份的本机会话。主号会话过期时保留当前小号，提供重新谷歌登录主号的入口。
- 切换前等待未提交的昵称等资料写入完成；延迟写入绑定原用户 ID，避免改名后立即切号写错身份。

## 后端

`supabase/functions/xuetuan-managed-alt/` 是专用 Edge Function。Gateway JWT 校验开启，函数内再次用 Auth `getUser` 验证访问令牌、非匿名身份、邮箱已验证和指定主号邮箱，随后从 Auth 管理接口读取最新主号信息。请求不能传入主号 ID 或目标账号 ID。

关联只写 Auth 的服务端 `app_metadata`，不信任可由用户编辑的 `user_metadata`。主号存 `xuetuan_alt_id`，小号存 `xuetuan_owner` 和 `xuetuan_managed_alt`。无新增业务表、RLS 或授予管理员权限的迁移。

小号使用不可收信的内部地址标识，用户界面不显示这个地址；密码为服务端随机值，不返回前端。后端仅为核验通过的主号生成小号的一次性登录令牌并交换会话，不发送邮件。服务密钥只来自 Edge Function 环境变量。返回会话设置 `Cache-Control: no-store`，不写日志。

原账号／照片删除仍走现有人工请求流程；处理主号删号时，也应按 `xuetuan_alt_id` 删除关联小号并撤销会话。

## 验证

- `node tests/test_managed_alt.mjs`：后端 13 项，涵盖未登录、非主号、游客、未验证邮箱、跨来源、唯一小号、无邮件和错误关联拒绝。
- `python tests/test_managed_alt.py`：手机原生点击 15 项，涵盖切换、记录隔离、管理员不继承、独立昵称、快速切换复用、会话过期恢复与退出清理。
- 只用合成身份验证；真实小号将在主号第一次点击切换时创建，未代替用户登录或读取其真实会话。
